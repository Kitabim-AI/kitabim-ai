# Legacy Book Surya OCR Backfill, Printed-Page Alignment, and Section-Aware Indexing

* **Author:** Omarjan
* **Date:** 2026-11-08

## Overview

Kitabim.AI stores over 900 books in production PostgreSQL whose text was extracted using either Gemini Vision OCR or an earlier un-tuned Surya setup. Meanwhile, the local desktop client ([clients/kitabim-ocr/](../../../clients/kitabim-ocr)) now runs an improved Surya 2.5 (`surya-ocr==0.23.0`) Uyghur OCR pipeline ([recognize.py](../../../clients/kitabim-ocr/engine/recognize.py), [text_cleanup.py](../../../clients/kitabim-ocr/engine/text_cleanup.py), [line_ends.py](../../../clients/kitabim-ocr/engine/line_ends.py)) with bleed-through suppression, diacritic dot enhancement, Table-of-Contents (ToC) pipe-table recovery, and hallucination filtering.

This initiative upgrades the 900+ legacy production PDF books using a headless sequential batch command on local hardware paired with a bulk book-OCR replacement endpoint on [services/backend/](../../../services/backend), avoiding a dedicated server-side OCR container. Before running the corpus backfill, the backend pipeline is streamlined—removing unused **History Concept Extraction** and **LLM Spell-Check** pipeline steps while adding a dedicated book-level **Structure Analysis** stage (`structure_milestone`) between OCR/dictionary spell-check and chunking to solve three existing limitations:
1. **Printed-to-physical page mapping:** Capture printed page numbers discarded during OCR from headers, footers, and page edges as sidecar metadata (`contentPageNumber`), smooth them across each book using piecewise-monotonic sequence fitting and ToC-anchor matching, and store per-page printed numbers in [`Page.content_page_number`](../../../packages/backend-core/app/db/models.py) instead of relying on a single book-wide [`Book.content_page_offset`](../../../packages/backend-core/app/db/models.py).
2. **Deterministic book structure extraction:** Extract poems, stories, and chapters into a `book_sections` table in PostgreSQL with zero LLM calls by reconciling ToC entries against in-page headings, falling back to Markdown (`##`) and Uyghur heading detection when a book lacks a ToC.
3. **Section-stream chunking with cross-page paragraph stitching:** Feed each `book_section` (rather than isolated pages) into [`ChunkingService._pack_adaptive`](../../../packages/backend-core/app/services/chunking_service.py) so two poems, stories, or chapters never share a chunk, paragraphs split across physical page breaks stay intact within a single chunk, and RAG retrieval can filter by `section_id` or return the full text of a named poem directly.

## Analysis

Six independent Goldfish reviews (`egm-design`, `egm-codebase-details`, `egm-zoom-out`, `egm-comprehension`, `egm-implementation-readiness`, and `egm-structural`) audited this concept against the codebase, refined by follow-up scope alignment (excluding Neo4j compatibility constraints, adding a dedicated structure-analysis pipeline stage, and retiring History Concept Extraction and LLM Spell-Check from the pipeline).

### 1. Streamlined Pipeline Order: Adding Structure Analysis and Retiring History Extraction & LLM Spell-Check
Today, [`chunking_scanner.py`](../../../services/worker/scanners/chunking_scanner.py) waits for page-level `spell_check_milestone` (because Uyghur auto-correct rules rewrite typos in `page.text`) and then claims arbitrary 100-page slices across books for [`chunking_job.py`](../../../services/worker/jobs/chunking_job.py). Page-isolated chunking combined with `CHUNK_SIZE = 1000` (which [`ChunkingService._pack_adaptive`](../../../packages/backend-core/app/services/chunking_service.py) treats as an upper pre-flush cap) currently produces fragmented chunks (median `438` chars / mean `546` chars across existing DB chunks, vs. median `1,405` chars per printed page) and chops cross-page prose paragraphs whenever a paragraph continues from page `N` onto page `N + 1`. Meanwhile, [`worker.py`](../../../services/worker/worker.py) still registers dead/unused pipeline tasks and cron pollers for **History Concept Extraction** and **LLM Spell-Check**.

The updated book pipeline becomes:
`Page OCR -> Page Dictionary Spell-Check/Auto-Correct -> Book Structure Analysis (printed-page alignment + book_sections) -> Section-Stream Chunking -> Embedding`

Key mechanics and cleanup boundaries:
* **Why Structure Analysis follows Dictionary Spell-Check (and runs on all books):** Running after `spell_check_milestone` finishes across a book's pages ensures Uyghur auto-correct rules fix common OCR typos in ToC rows and `##` headings *before* deterministic ToC-to-heading matching runs. Every book in the catalog—including `surya_local` books uploaded on or after `2026-11-08` (which skip Phase 2 re-OCR), `.docx` books, new uploads (`upload-ocrd`, `upload`), and backfilled legacy PDFs—executes `Book.structure_milestone` followed by section-stream chunking and embedding.
* **Intra-section block parsing, page-local footnotes, cross-page stitching, and Uyghur-tuned chunk sizing:** Within each leaf `book_section`, parse each page slice into blocks (headings, prose paragraphs, poem stanzas, tables, footnotes) and attach `① ② ③` footnotes to their referencing paragraph *per page first* ([`_attach_footnotes_to_blocks`](../../../packages/backend-core/app/services/chunking_service.py), since footnote markers restart on later pages). Next, stitch the final prose block of page `N` with the leading prose block of page `N + 1` when neither block is verse, table, or footnote, no heading/`is_toc`/blank page separates them, and page `N`'s final block either ends with a line-break hyphen or lacks terminal sentence punctuation (`۔`, `.`, `!`, `؟`, `:`), then pack blocks directly via [`_pack_adaptive`](../../../packages/backend-core/app/services/chunking_service.py) (bypassing [`split_text`](../../../packages/backend-core/app/services/chunking_service.py)'s unstructured character-splitter fallback). Tune sizing for Uyghur morphology and `gemini-embedding-2` (`8,192`-token input limit): **`CHUNK_SIZE = 1500`** (yielding `1,000–1,450` actual chars per prose chunk, ~1 printed page, while keeping standalone poems up to ~20 couplets in a single chunk), **`CHUNK_OVERLAP = 200`**, **`CHUNK_MIN_SIZE = 350`** (merging trailing leftovers only within the same section), and **`_EMBED_SAFE_CHARS = 4000`** (up from `2,600`, keeping long paragraphs with historical footnotes whole). *Known text-only limitation:* Because `Page.text` Markdown does not store visual first-line indentation, a cross-page paragraph that ends a complete sentence on the final word of page `N` splits cleanly at that sentence boundary rather than risking merging two distinct paragraphs.
* **Chunk schema, citations, and hash-preserved edits:** Keep `Chunk.page_number = start_page` (`NOT NULL`, preserving `UniqueConstraint(book_id, page_number, chunk_index)` and opening the starting page on `ref:book_id:page_number` citation clicks in [`answer_builder.py`](../../../packages/backend-core/app/services/rag/answer_builder.py)) and add `end_page_number` plus `section_id`. Unify single-page mutation paths ([`update_page_text`](../../../services/backend/api/endpoints/books_router.py), [`apply_spell_corrections`](../../../services/backend/api/endpoints/spell_check_router.py), [`AutoCorrectService`](../../../packages/backend-core/app/services/auto_correct_service.py), [`set_page_toc`](../../../services/backend/api/endpoints/books_router.py)): toggling `is_toc` or editing headings resets `Book.structure_milestone = 'idle'`, whereas body typo edits re-chunk only the enclosing `book_section` and carry forward existing `Chunk.embedding` vectors whenever `sha256(normalized_chunk_text)` matches—so a 1-word edit on page 40 re-embeds only the 1–2 altered chunks. Ensure `embedding_job.py` / `batch_embedding_service.py` evaluate completion across all chunks of the book/section rather than assuming every continuation page anchors its own `Chunk` row.
* **Complete Removal of History Concept Extraction (Including Staging Queue UI) & All LLM-Based Spell-Check:**
  * *Full LLM spell-check removal (end-to-end):* Remove `llm_spell_check_job` and `run_batch_llm_spell_check_poller_scanner` from [`worker.py`](../../../services/worker/worker.py); remove `llm_spell_check_service.py` and `batch_llm_spell_check_service.py`; remove both `POST /api/books/{book_id}/reprocess/llm-spell-check` ([`books_router.py`](../../../services/backend/api/endpoints/books_router.py)) and `POST /api/books/{book_id}/pages/{page_num}/llm-spell-check/preview` ([`books_router.py`](../../../services/backend/api/endpoints/books_router.py)); remove the Reader edit-mode "LLM Check" UI in [`PageItem.tsx`](../../../apps/frontend/src/components/reader/PageItem.tsx) / [`ReaderView.tsx`](../../../apps/frontend/src/components/reader/ReaderView.tsx) and the Admin `ActionMenu` / `REPROCESS_STEP` entries; and drop `Page.llm_spell_check_status`, `Page.llm_spell_check_at`, and `BatchLlmSpellCheckJob`.
  * *Full LLM History Concept Extraction & Staging Queue removal (keeping static `HistoryDictionary` intact):* Unregister `extract_book_history_terms_task` and `run_batch_history_poller_scanner` from [`worker.py`](../../../services/worker/worker.py); remove `history_extraction_service.py`, `batch_history_extraction_service.py`, `dictionary_staging_service.py`, and `admin_history_dictionary_router.py` (`/api/books/{book_id}/extract-history` and `/api/admin/history-dictionary/staging/*`); remove the staging queue page and extraction controls (`HistoryStagingQueuePanel.tsx`, the `history-staging` tab in [`DictionaryView.tsx`](../../../apps/frontend/src/components/pages/DictionaryView.tsx), Admin book `ActionMenu` "Extract History" item, and `history_*` extraction system config controls); and drop `HistoryDictionaryStaging` and `BatchHistoryExtractionJob`. The static imported Historical Vocabulary Dictionary feature ([`HistoryDictionaryPanel.tsx`](../../../apps/frontend/src/components/admin/dictionary/HistoryDictionaryPanel.tsx), the `history` tab in [`DictionaryView.tsx`](../../../apps/frontend/src/components/pages/DictionaryView.tsx), `/api/history-dictionary`, and `history_dictionary` table from migrations `060`–`061`) stays intact.
  * *Remove unused Hypothetical Questions from `BookSummary`:* Remove Section 6 (`Hypothetical Queries` / `تىپىك سوئاللار`) from [`BOOK_SUMMARY_PROMPT`](../../../packages/backend-core/app/core/prompts.py) (rewriting the system prompt strictly in English per repository rules while requiring Uyghur Arabic-script output, renumbering `Keywords` to Section 6), and strip existing `6. تىپىك سوئاللار` sections (renumbering `7.` -> `6.`) from persisted `book_summaries.summary` text via SQL migration so library/citation summary modals no longer display 20–30 unused questions without re-running Gemini on existing books.

### 2. Live Public Book Visibility and Unintended LLM Bills via `Book.status` (Blocker)
`Book.status` currently conflates public catalog availability with worker retry eligibility:
* **Catalog disappearance vs. stuck retries:** Public library, reader, and search endpoints ([`books_router.py`](../../../services/backend/api/endpoints/books_router.py), [`pages_repository.py`](../../../packages/backend-core/app/db/repositories/pages_repository.py)) hide any book where `Book.status != 'ready'`. Resetting `Book.status` to `'ocr_done'` or `'pending'` during `POST /api/books/{book_id}/replace-ocr` unpublishes live books from the library and reader. Conversely, keeping `Book.status = 'ready'` causes [`pipeline_driver.py`](../../../services/worker/scanners/pipeline_driver.py) to skip failure retries.
* **Unintended LLM Summary and Graph triggers:** Transitioning a book back to `'ready'` in [`pipeline_driver.py`](../../../services/worker/scanners/pipeline_driver.py) resets `graph_milestone = 'idle'`, while [`summary_scanner.py`](../../../services/worker/scanners/summary_scanner.py) enqueues LLM `summary_job` for any `'ready'` book without a `BookSummary` row.
* **Required mitigation:** Keep already-public books at `Book.status = 'ready'` during `replace-ocr`; widen `pipeline_driver` and `stale_watchdog_scanner.py` to monitor and retry `structure_milestone`, `chunking_milestone`, `embedding_milestone`, and `spell_check_milestone` on `'ready'` books without touching `graph_milestone` or triggering `summary_scanner`; and re-index books sequentially **one book at a time** in place using book-scoped chunking and book-scoped `BatchEmbeddingJob` (`embed_batch_enabled = 'true'` in production at `\$0.10`/1M tokens, with online `64`-chunk `:batchEmbedContents` fallback when `'false'`) while throttling CLI backpressure only on unsubmitted worker backlog.

### 3. Headless CLI Blockers: 60-Minute OAuth Expiry and 0-Byte HTTP 307 Downloads (Blocker)
Processing ~225,000–270,000 pages sequentially on local Apple Silicon/GPU (`MAX_SURYA_PARALLEL_PAGES = 4`) takes roughly 65–160 hours (3–7 days) and hits two defects in [`clients/kitabim-ocr/kitabim_client/`](../../../clients/kitabim-ocr/kitabim_client):
* **Browser-only 60-minute JWT expiry:** [`get_valid_token`](../../../clients/kitabim-ocr/kitabim_client/auth.py) caches only a 60-minute `access_token` (`jwt_access_token_expire_minutes = 60` in [`config.py`](../../../packages/backend-core/app/core/config.py)) with no refresh token, then calls `webbrowser.open()` and raises `AuthError` after 120 seconds. Fix CLI auth by issuing and persisting a rotatable OAuth `refresh_token` alongside `access_token` in `token.json` (via backend loopback auth + refresh endpoint) so expired tokens auto-renew headlessly without opening a browser.
* **Unfollowed HTTP 307 GCS redirect writes 0-byte PDFs:** [`download_book`](../../../services/backend/api/endpoints/books_router.py) returns an HTTP `307` redirect to Google Cloud Storage in production. [`KitabimClient.download_book_pdf`](../../../clients/kitabim-ocr/kitabim_client/api.py) calls `httpx.get` with `follow_redirects=False` and writes `b""` (0 bytes) to disk because `307 < 400`. It must stream to disk with `follow_redirects=True` (or download-ticket flow) and verify `%PDF` magic bytes.
* **API routing, legacy eligibility cutoff, and safe CLI controls:** Middleware [`security_block_prefixes`](../../../packages/backend-core/app/core/config.py) blocks `/api/bulk/`, `/api/batch/`, and `/api/import/` with HTTP 404, so the bulk endpoint must live at `/api/books/{book_id}/replace-ocr` using compressed/multipart JSON and a single batched PostgreSQL `ON CONFLICT DO UPDATE` query. Server-side backfill eligibility skips non-PDF books (`file_type != 'pdf'`), skips `source == 'surya_local'` books uploaded on or after `2026-11-08`, and skips books already stamped with the new `Book.ocr_version`—treating all other PDFs (including pre-`2026-11-08` `surya_local` books) as legacy candidates without offset drift as books update. The CLI also includes `--dry-run`, `--book-id`, `--limit`, server embedding backlog backpressure checks, and `try/finally` local cleanup on `SIGINT`/`SIGTERM`.

### 4. Sidecar Page-Number Capture Order, Text-Cleanup Drift, and Reader ToC Navigation (Major)
* **Capture order and bleed-through filtering in `recognize.py`:** [`DISCARD_LABELS = {"PageHeader"}`](../../../clients/kitabim-ocr/engine/recognize.py) drops top-margin headers at line 1395 *before* inspecting `block.html`, [`PageFooter`](../../../clients/kitabim-ocr/engine/recognize.py) checks isolated numbers *before* [`_is_phantom_bleed_through_block`](../../../clients/kitabim-ocr/engine/recognize.py) (risking faint mirrored verso page numbers), and top/bottom `Text` page numbers are stripped later in [`strip_page_numbers`](../../../clients/kitabim-ocr/engine/text_cleanup.py). Sidecar capture must inspect all three sources *after* phantom bleed-through checks, keep `ocr_page() -> str` and `OcrWorkDir` backward-compatible via an optional helper/field, and persist raw `Page.detected_page_number` separately from fitted `Page.content_page_number` so `structure_milestone` can re-run from PostgreSQL state alone without re-OCRing PDFs.
* **Client/server text-cleanup drift:** [`clients/kitabim-ocr/engine/text_cleanup.py`](../../../clients/kitabim-ocr/engine/text_cleanup.py) and [`packages/backend-core/app/utils/text.py`](../../../packages/backend-core/app/utils/text.py) have drifted (`backend-core`'s `clean_uyghur_text` joins non-poem lines into single paragraphs and its `parse_toc_entries` misses Eastern Arabic/Persian numerals). Numeral normalization, pipe-table ToC detection, and heading extraction must share unified rules and execute before paragraph line-reflow.
* **Reader ToC click navigation and repurposing the "Mark as Page 1" button:** [`MarkdownContent.tsx`](../../../apps/frontend/src/components/common/MarkdownContent.tsx) currently only enables clickable ToC rows when `contentPageOffset > 0` (`contentPageNum + contentPageOffset`), and [`ReaderView.tsx`](../../../apps/frontend/src/components/reader/ReaderView.tsx) / [`PageItem.tsx`](../../../apps/frontend/src/components/reader/PageItem.tsx) renders an editor "Mark as Page 1" (`handleSetStartPage`) button that only sets `Book.content_page_offset`. Return a book-wide `contentPageMap` on `GET /api/books/{book_id}` so [`VirtualScrollReader.tsx`](../../../apps/frontend/src/components/reader/VirtualScrollReader.tsx) resolves Reader ToC clicks directly to unloaded physical pages, and repurpose the plain one-click "Mark as Page 1" modal so confirming on physical page `P` backfills `Page.content_page_number` across the book (`NULL` for `page_number < P` and `"1", "2", "3", ...` from `P` onward), records `content_page_number_manual = TRUE` so future `Book.structure_milestone` runs preserve manual overrides, and triggers `Book.structure_milestone` to re-align `book_sections`.

### 5. Header-Driven Detection for ToC-Less Books, Anthology Edge Cases, Dehyphenation, and Quotas (Major)
* **Header-Driven chapter & individual-work detection when a book lacks a ToC (or has a chapter-only ToC):**
  * *Preserving Surya layout headers in OCR:* Today, [`_block_html_to_markdown`](../../../clients/kitabim-ocr/engine/recognize.py) only outputs `#` / `##` when `block.html` contains `<h1>..<h6>` tags; if Surya labels a block `"Title"` or `"SectionHeader"` with `<p>` or plain text inside, the Markdown header prefix is silently dropped. Update `_block_html_to_markdown` so `"Title"` and `"SectionHeader"` blocks consistently emit `#` / `##` Markdown headers (matching `.docx` `##` headings from [`extract_docx_pages`](../../../packages/backend-core/app/services/docx_service.py)).
  * *Two-tier header structure builder:* When a book has no `is_toc` pages—or when its ToC lists only top-level parts/chapters while individual poems or stories sit inside each part—`Book.structure_milestone` builds `book_sections` directly from in-page headers across two levels:
    1. **Chapters and parts:** Markdown `#` / `##` headers or standalone Uyghur structural markers expanding [`_UYGHUR_HEADING_RE`](../../../packages/backend-core/app/services/chunking_service.py) (`باب`, `قىسىم`, `بۆلۈم`, `پەسىل`, `مۇقەددىمە`, `خاتىمە`, `كىرىش سۆز`, plus numbered/Roman ordinals such as `1 - باب`, `I.`, `1.`).
    2. **Individual works (poems, stories, essays):** Remaining `##` / `###` header blocks after deterministic noise filters reject trailing poem dates/locations (`1985-يىل ...`), author bylines, ornamental dividers (`* * *`), and repeated running headers across page tops.
* **Multi-poem pages, duplicate titles, and rollout coexistence:** Uyghur poetry collections frequently print 2–4 short poems on one physical page and repeat titles such as `«غەزەل»` or `«رۇبائىي»`. `book_sections` must store intra-page block indices (not raw character offsets that break on edits, and not whole-page numbers alone), constrain ToC-to-heading matching (when a ToC exists) to piecewise-monotonic `±1–2` page windows, run `structure_milestone` across all existing books (including `surya_local` books uploaded on or after `2026-11-08` and `.docx` books) in Phase 1, and maintain fallback to [`toc_lookup_service.py`](../../../packages/backend-core/app/services/rag/toc_lookup_service.py) for any book whose `book_sections` has not yet run.
* **Dehyphenation boundary safety and GPU time:** Cross-page dehyphenation ([`read_line_end_words`](../../../clients/kitabim-ocr/engine/line_ends.py)) adds +35–50% GPU time if run unconditionally and corrupts words if run across a skipped cover/ToC or failed fallback page. Gate it strictly to contiguous freshly Surya-OCR'd body page pairs `(p, p+1)` where page `p` ends with a hyphen character.
* **Embedding quotas, Cloud SQL storage, telemetry, and rollback:** Re-index books sequentially using book-scoped `BatchEmbeddingJob` (`embed_batch_enabled = 'true'` in production, `embed_batch_max_chunks_per_job = 1000`, across ~240k–280k pure-text chunks / ~250M–350M Uyghur tokens, ~40–50% fewer rows than today's `546`-char mean chunks, at `\$0.10`/1M tokens ≈ `\$25–\$35` total across `946` legacy PDFs; with online `64`-chunk `:batchEmbedContents` fallback when `'false'`) while reusing vectors for unchanged `text_hash` values and throttling CLI backpressure only on unsubmitted worker backlog. Skip SQL `UPDATE`s on unchanged pages, confirm 15–20 GB Cloud SQL disk headroom for `Vector(3072)` HNSW dead tuples (followed by post-backfill `VACUUM ANALYZE` + `REINDEX INDEX CONCURRENTLY`), save a compact pre-backfill JSONL snapshot per book in GCS for single-book rollback (rather than bloating `Page.prev_text`), and log per-book/per-page decisions in an append-only local `backfill_audit.jsonl` correlated via `X-Request-ID`.

## Goals vs. Non-Goals

* **In-Scope Goals:**
  * Capture discarded `PageHeader`, `PageFooter`, and edge-line printed page numbers as optional `contentPageNumber` sidecar metadata in [clients/kitabim-ocr/](../../../clients/kitabim-ocr) after bleed-through filtering, and ensure Surya `"Title"` / `"SectionHeader"` layout blocks always emit `#` / `##` Markdown headers even when wrapped in `<p>`, keeping `page.text` and interactive `app`/`preview`/`push` workflows backward-compatible.
  * Add a dedicated book-level **Structure Analysis** worker stage (`Book.structure_milestone`) ordered after page OCR and dictionary spell-check/auto-correct and before chunking—executed across **all** books (including `surya_local` books uploaded on or after `2026-11-08` and `.docx` books)—storing raw `Page.detected_page_number`, solver-fitted `Page.content_page_number`, and deterministic (zero-LLM) `book_sections` via both ToC-to-header reconciliation and pure header-driven chapter/work detection for ToC-less or partial-ToC books (with intra-page block boundaries), while updating reader ToC click navigation and repurposing the Reader "Mark as Page 1" button to manually backfill `Page.content_page_number` (preserving manual overrides when `structure_milestone` re-runs).
  * Remove **LLM-based History Concept Extraction & Staging Queue end-to-end** (worker job/poller, `history_extraction_service.py`, `batch_history_extraction_service.py`, `dictionary_staging_service.py`, `admin_history_dictionary_router.py`, `HistoryStagingQueuePanel.tsx`, the `history-staging` tab in `DictionaryView.tsx`, Admin `ActionMenu` trigger, `history_*` config controls, and `HistoryDictionaryStaging` / `BatchHistoryExtractionJob` tables, while keeping the static `HistoryDictionary` feature and `HistoryDictionaryPanel.tsx` intact), remove **all LLM-based Spell-Check features end-to-end** across worker jobs/pollers, backend services/endpoints (`reprocess/llm-spell-check` and `pages/{page_num}/llm-spell-check/preview`), DB schema (`llm_spell_check_status`, `llm_spell_check_at`, `BatchLlmSpellCheckJob`), and frontend Reader/Admin UI, and remove unused **Hypothetical Questions (Section 6)** from [`BOOK_SUMMARY_PROMPT`](../../../packages/backend-core/app/core/prompts.py) and existing `book_summaries.summary` text.
  * Implement section-stream chunking (`Chunk.section_id`, `page_number = start_page`, `end_page_number`) tuned for Uyghur text (`CHUNK_SIZE = 1500`, `CHUNK_OVERLAP = 200`, `CHUNK_MIN_SIZE = 350`, `_EMBED_SAFE_CHARS = 4000`) with page-local footnote binding, deterministic cross-page prose paragraph stitching, hash-preserved embeddings on single-page edits, section-filtered RAG search, and exact poem/short-work lookup via `book_sections`.
  * Add a headless sequential backfill CLI command (with rotatable OAuth `refresh_token` auto-renewal, redirect-safe streaming PDF download, eligibility filtering that skips non-PDFs and `surya_local` uploads on or after `2026-11-08`, `--dry-run`/`--book-id`/`--limit`, server backlog backpressure, append-only local `backfill_audit.jsonl`, and immediate per-book temp-file deletion) paired with `POST /api/books/{book_id}/replace-ocr`.
  * Preserve page 1 covers, already pipe-formatted ToC pages, and existing server page text on local OCR failures; restrict cross-page dehyphenation to contiguous freshly OCR'd hyphenated body pages; archive pre-backfill book text to GCS for single-book rollback; keep public books visible in the library and reader (`Book.status = 'ready'`) while re-indexing books sequentially one by one in place; and skip `BookSummary` and Neo4j Knowledge Graph regeneration.
* **Out-of-Scope Non-Goals:**
  * Deploying or maintaining a server-side `kitabim-ocr` Docker container on local Docker Compose or GCP Compute Engine.
  * Re-OCRing `.docx` books or `surya_local` PDF books uploaded on or after `2026-11-08` (though they still run `Book.structure_milestone` and section-stream chunking).
  * Preserving or updating Neo4j Knowledge Graph chunk-reference compatibility (`get_graph_chunk_detail`) or regenerating Knowledge Graphs and `BookSummary` rows during backfill.
  * Changing web-UI PDF upload (`POST /api/books/upload`), which remains low-priority on Gemini OCR.
  * Using LLM calls for book section/heading detection.
  * Retaining downloaded PDFs or rendered preview PNGs on local disk after a book's bulk OCR update succeeds.

## Alternatives Weighed

* **Dedicated server-side `services/kitabim-ocr` Docker container on production:** Rejected because Surya 2.5 (`surya-ocr==0.23.0`) requires 4–8 GB RAM/VRAM and heavy compute; running ~250,000 pages on the CPU-only GCP Compute Engine VM would saturate CPU for weeks and risk OOM contention alongside other containers, while an always-on cloud GPU VM costs hundreds of dollars per month for acceleration already available locally at zero cost. Server-side `reset_page` also blanks live `Page.text` during processing and risks duplicating 3,000+ lines of OCR engine heuristics.
* **Page-isolated chunks with intra-page section tags only (Option 1B):** Weighed as a simpler alternative to avoid changing page-level chunking scanners, then rejected because `ChunkingService._pack_adaptive` is designed to keep paragraphs whole up to `_EMBED_SAFE_CHARS`, and page-isolated chunking splits cross-page prose paragraphs mid-sentence at every page turn (contributing to today's fragmented `438`-char median chunk size) while Neo4j chunk-ref coupling does not need to be preserved.
* **Keeping legacy `CHUNK_SIZE = 1000` / `_EMBED_SAFE_CHARS = 2600`:** Rejected because `_pack_adaptive` flushes before exceeding `CHUNK_SIZE` (causing multi-paragraph chunks to flush early around `500–850` chars and splitting 15–20 couplet ghazals in two), whereas `gemini-embedding-2` supports `8,192` input tokens and `CHUNK_SIZE = 1500` / `_EMBED_SAFE_CHARS = 4000` produces ~`1,000–1,450`-char chunks (~1 printed page) while cutting `Vector(3072)` row/index overhead by ~40–50%.
* **Pushing existing books via per-page `POST /api/books/{book_id}/pages/{page_num}/update`:** Rejected because `KitabimClient.push_page_correction` issues two sequential HTTP POSTs per page (~450,000 requests across 900 books) and triggers synchronous Gemini Embedding calls and full book milestone recalculations on every single page.
* **Running the 900-book OCR backfill before updating structure and chunking logic:** Rejected because pushing updated OCR text under legacy chunking and changing chunking afterward would force re-chunking and paying Gemini Embedding costs across ~200M–350M tokens twice.
* **Storing entire chapters or multi-page stories as single chunks:** Rejected because even with `gemini-embedding-2`'s `8,192`-token input window, multi-page prose chapters exceed token limits on longer chapters and single-vector embeddings lose fine-grained scene recall compared to ~1-page (`1,000–1,450`-char) chunks.
* **LLM-assisted section and heading extraction:** Rejected to avoid LLM cost, latency, and non-determinism across 900+ books in favor of deterministic ToC reconciliation + filtered header detection.
* **Backend-only ToC-to-heading page offset solver without OCR sidecar page numbers (Approach A):** Rejected because books lacking a printed ToC would receive no printed page mapping, whereas Surya already detects `PageHeader`/`PageFooter` numbers before discarding them.
* **Removing the Reader "Mark as Page 1" button outright:** Rejected because some scans have cropped margins, missing printed page numbers, or unreadable headers; repurposing the button to backfill `Page.content_page_number` gives editors a one-click manual fallback without relying on legacy `Book.content_page_offset`.
* **Static operator/API token in `.env` for headless CLI auth:** Rejected in favor of rotatable OAuth `refresh_token` persistence in `token.json`, avoiding long-lived unrotated static credentials on disk while fixing 60-minute session logouts for interactive `kitabim-ocr` commands as well.
* **Storing pre-backfill text backups in `Page.prev_text` inside PostgreSQL:** Rejected because duplicating ~250,000 pages inline adds 500 MB–1 GB of permanent table/WAL bloat to Cloud SQL compared to a compact per-book JSONL snapshot in GCS.
* **Zero-downtime shadow staging (`chunks_staging` table or `Chunk.generation` column):** Rejected because zero-downtime vector search per individual book is not required; book-scoped `BatchEmbeddingJob` (`embed_batch_enabled = 'true'` at `\$0.10`/1M tokens) paired with unsubmitted-worker-backlog CLI backpressure preserves the 50% Gemini batch discount without stalling local GPU OCR or adding staging tables, generation columns, or double-row HNSW index bloat.
